# VideoExpress Shorts Checklist

## Before production
- [ ] Story has a strong opening hook, clear action, emotional turn, and satisfying ending.
- [ ] Duration and aspect ratio are known; default to vertical 9:16.
- [ ] For animal workflows, animal identity, markings, accessories, and style are consistent.
- [ ] Any user-provided reference image is used as requested.
- [ ] Every scene has an incoming state, new action, outgoing state, and handoff.
- [ ] Image prompts and motion prompts are separate and specific.
- [ ] Narration/audio choice is clear.
- [ ] “AJ-AI” branding is subtle and placed where it can render legibly.

## During generation
- [ ] Use only the concurrent job count shown by the active account.
- [ ] Track each job by scene and status.
- [ ] Wait when the queue is full; do not submit duplicates.
- [ ] Inspect uncertain jobs before retrying.
- [ ] Retry only failed or clearly unusable clips, up to three attempts total per scene.
- [ ] Preserve completed assets.

## Before export — required timeline and rendered-video QA

- [ ] Every submitted job has a known result.
- [ ] Match visible clip content to the numbered storyboard; verify hook, escalation, turn, and payoff order.
- [ ] Confirm each planned usable clip appears exactly once; account for missing, failed, intentionally omitted, or duplicate scenes.
- [ ] Check clip boundaries and durations; run Auto Align or equivalent, then recheck.
- [ ] Check for unintended gaps, overlaps, blank/black frames, frozen holds, repeated footage, abrupt cuts, and cut-off action/audio; remove unwanted waiting time.
- [ ] Play the timeline from the beginning through the end when practical. At minimum inspect the opening, key joins, turn, and ending.
- [ ] Confirm intended audio placement and no accidental duplicates.
- [ ] Save and verify the visible saved state before exporting.

## After export — verify the rendered file

- [ ] Wait for the export to finish; open the new rendered output itself.
- [ ] Confirm it opens and check displayed runtime and format/aspect ratio when available.
- [ ] Review the rendered video end to end when practical. Otherwise seek to and inspect the opening, every scene boundary/major transition, the turn, and final seconds.
- [ ] Compare rendered order with the storyboard and timeline; confirm the reveal/turn precedes the intended payoff and the final shot is correct.
- [ ] Check rendered playback for unwanted waiting, frozen/blank frames, accidental pauses, abrupt cuts, repeated/missing scenes, and missing or cut-off audio.
- [ ] If a defect is found, correct the timeline, save, export again, and repeat this rendered-file check.
- [ ] Record any check that was unavailable; do not claim it passed.
## Cross-platform publishing: Facebook Reels + YouTube Shorts

Create one clean shared master, then prepare platform-specific upload details.

- **Shared master:** vertical 9:16, 1080×1920 MP4 when VideoExpress offers it. Keep key faces, action, captions, and logos near the center with comfortable space at the top and bottom for app controls.
- **Shared length:** default to 30–45 seconds. Keep a cross-posted cut under 90 seconds for a comfortable common target; check the current upload flow if the user requests a longer cut. YouTube currently classifies square or vertical uploads up to 3 minutes as Shorts; Facebook's Help Center currently describes Reels up to 90 seconds. Platform limits can change.
- **Make clean exports:** avoid another platform's watermark, end card, or baked-in follow prompt. Use original or properly licensed audio that can be used on both services; otherwise export without music and add platform-cleared audio natively for each upload.
- **Captions:** use accurate captions or subtitles when available, proofread them, and keep them clear of interface overlays. Keep essential visual information understandable without sound.
- **Prepare two upload packages:** YouTube gets its own concise title, description, and relevant hashtags; Facebook gets its own caption/description and relevant hashtags. Keep the video itself the same unless a platform-specific edit is requested.
- **Publishing is a separate step:** these workflows prepare the video and copy. Upload or publish only when the user asks; never claim it was posted unless the platform confirms it.

## Report honestly
- [ ] State actual runtime and scene count when available.
- [ ] State whether timeline completeness and export were verified.
- [ ] Note any unavailable quality checks or remaining issues.

## Additional checks for stickman couple comedy

- [ ] Actual approved permanent-couple reference identified and inspected, reused across stories and all clips; no silent new masters.
- [ ] Both spouses match the existing minimal circle-head/line-body style, with complete arms/legs and stable identity/hair cues and ponytail; outfits suit the situation and stay consistent across connected clips; neither spouse wears glasses.
- [ ] Reference selection and capacity verified; room reference never displaced the couple.
- [ ] Dialog ratio checked independently and image enhancement OFF before each source submission.
- [ ] Planned runtime/scene count honor the request; actual durations recorded instead of assumed.
- [ ] At most five concurrent video jobs, or lower visible account limit; private scene ledger used.
- [ ] Set, facing, gaze and contact points continue; food/props do not appear before introduction.
- [ ] Each source passed review before animation; source/video corrections bounded to three total attempts per scene.
- [ ] Dialogue-led treatment and speaker assignments retained; unsupported audio features disclosed.
- [ ] All assets added exactly once with each addition checked, including the final punchline.
- [ ] Subtitles match spoken words, spelling, timing and vertical safe margins; unsupported captions reported.
- [ ] Suitable included music, when available/cleared, stays below speech.
- [ ] Actual exported MP4 checked for blank/dark sections, bars, missing ending, identity/style drift, pauses, subtitle and audio defects.
- [ ] Passed checks distinguished from unverified ones; no claim of playback/audio inspection without evidence.

## Waiting for asynchronous jobs and export

- [ ] Each scene tracked separately; mixed completion times expected even when five jobs were submitted together.
- [ ] Queued/rendering jobs revisited after short waits; completed clips retained while remaining jobs finished.
- [ ] No more than five concurrent jobs or the lower visible account limit.
- [ ] No duplicate submissions, premature failure claims or generation retries solely because a job was still processing.
- [ ] All planned jobs reached known results before timeline completeness was claimed.
- [ ] Export submitted once, tracked individually and rechecked after waits while still processing.
- [ ] Existing exports inspected before any retry; actual completed output opened and checked before claiming delivery.
- [ ] During extended waits, progress updates named completed/total clips or export status; any concrete monitoring blocker reported with preserved progress.

## Stickman UI selection and prompt requirements

- [ ] VideoExpress Image Type **Other** visibly selected; the **2D** preset was not selected.
- [ ] **Consistent Character ON** and approved couple image actually selected/uploaded; reference thumbnail verified for scene 1 and retained/restored throughout.
- [ ] Each image and motion prompt explicitly says neither spouse wears glasses (including eyeglasses/sunglasses); this instruction is not spoken or captioned.
- [ ] Source images and rendered clips checked against the reference for identity and absence of glasses; material mismatches corrected within bounded retries.
- [ ] Missing Other/reference controls reported as a concrete limitation rather than silently substituting settings or generating unreferenced clips.
